# 模板使用指南：从约束、转化到正确实现

模板库真正要解决的不是“代码在哪”，而是四个问题：**为什么想到它、使用前提是什么、维护的信息为什么够、改题时最容易破坏哪个不变量。**

## 一、先用约束排除不可能

以下只是常见量级，常数、语言和测试组数会改变结论：

| 数据规模 | 常见可接受方向 |
|---:|---|
| `n <= 10` | 全排列、搜索、状态图 |
| `n <= 20~25` | `2^n` 状压、折半搜索 |
| `n <= 200~500` | `O(n^3)` Floyd、区间 DP、高斯消元 |
| `n <= 3000~10000` | 经过优化的 `O(n^2)` DP |
| `n,m <= 2e5` | `O(n log n)`、`O((n+m)log n)` |
| `n <= 1e6` | 线性、筛法、简单双指针 |
| 值域/时间到 `1e18` | 二分答案、数学化、矩阵幂、周期性 |

先把总复杂度写出来：`测试组数 × 状态数 × 每状态转移数`。只看单组 `n` 是最常见的误判。

## 二、读题后固定问六个问题

1. **对象是什么？** 连续区间、集合、图、树、字符串、数位还是几何对象？
2. **操作是静态还是动态？** 只查询、单点改、区间改、加边、删边还是离线可排序？
3. **答案是否单调？** 若 `x` 可行时更大的都可行，考虑二分答案。
4. **局部修改影响多远？** 只影响前缀、祖先链、邻接点、固定长度历史，还是整个状态？
5. **能否合并？** 若一个区间/子树的信息能由两个子块合并，考虑 DP、线段树或分治。
6. **真正的瓶颈是什么？** 是不会算法，还是证明贪心、状态太多、实现过长、容易对拍？

只有回答完这六问，模板才是加速器；否则它只是更快地产生 WA。

## 三、区间题怎样选数据结构

| 操作 | 首选 | 为什么 |
|---|---|---|
| 静态区间和 | 前缀和 | 两个前缀相减，`O(1)` 查询 |
| 多次区间加、最后统一取值 | 差分 | 每次只改两端 |
| 单点加、区间和 | Fenwick | 短、常数小、容易默写 |
| 静态 min/max/gcd | ST 表 | 幂等运算允许两个重叠块 |
| 区间改、区间问 | 懒线段树 | 节点信息可合并，修改可作用整段 |
| 静态区间第 k 小 | 主席树 | 前缀版本相减得到区间频次 |
| 离线询问且端点可快速增删 | 莫队 | 调整询问顺序减少总移动量 |
| 动态加直线、点查询最值 | Li Chao | 在 x 域上维护哪条线更优 |

线段树动手前必须写出三件事：

```text
Node 维护什么？
merge(left, right) 为什么足够？
新 lazy 操作怎样与旧 lazy 操作复合？
```

例如 [01 序列线段树](../03-silver/binary_sequence_segment_tree.cpp) 同时维护 0/1 的最长前缀、最长后缀和最长连续段：

```text
best = max(left.best, right.best, left.suf + right.pre)
pre  = left 整段同值 ? left.len + right.pre : left.pre
suf  = right 整段同值 ? right.len + left.suf : right.suf
```

赋值会覆盖历史操作；翻转接在 `set(v)` 后等价于 `set(v xor 1)`。把懒标记看作函数复合，比死记 `down()` 顺序可靠。

## 四、最短路与连通性怎样选

| 图的性质 | 算法 |
|---|---|
| 无权图 | BFS |
| 边权只有 0/1 | 0-1 BFS |
| 非负权稀疏图 | Dijkstra |
| 有负边、需要判可达负环 | Bellman-Ford |
| 点数小、全源最短路 | Floyd |
| 不等式 `x[v]-x[u] <= w` | 差分约束，建边 `u -> v (w)` |
| 无向动态连通、只加边 | 普通 DSU |
| 离线加删边 | 时间线分治 + 可撤销 DSU |
| 删除某条边/某个点是否断开 | 桥与割点 |
| 有向图互相可达 | SCC 缩点 |

最短路的 `dis` 默认用 `long long`。只有在 `dis[x] != INF` 时才能做 `dis[x] + w`，否则哨兵值也可能参与溢出。

## 五、树题先决定信息方向

树上问题常见的五种方向：

- **从祖先跳转**：LCA / 倍增。
- **从儿子合并到父亲**：树形 DP。
- **每个点都作为根**：先子树 DP，再换根。
- **路径拆成少量连续区间**：树链剖分。
- **大量子树频次统计**：Euler 序 + DSU on tree。

看到“对每个点求答案”不要马上 `n` 次 DFS。先尝试写出父根答案移到儿根时，哪些点距离或贡献增加、哪些减少。[换根距离和](../03-silver/rerooting_dp.cpp) 的核心式只有一行：

```text
ans[child] = ans[parent] + n - 2 * size[child]
```

树递归深度可能到 `2e5`；现场环境栈较小时要改显式栈，或确认平台允许更大栈。

## 六、DP 不从“套类型”开始

DP 的顺序应当是：

1. 写一句状态语义，包含“处理到哪里”和“已经记录了什么”。
2. 证明未来只依赖这些信息，没有遗漏历史。
3. 写初值和无效状态。
4. 写转移方向，确认一个状态会不会被本轮重复使用。
5. 最后才决定滚动数组、矩阵幂、单调队列或分治优化。

常见触发：

| 信号 | 方向 |
|---|---|
| 每件物品选或不选 | 0/1 背包，容量倒序 |
| 物品可重复 | 完全背包，容量正序 |
| `n <= 20`，状态由已选集合决定 | 状压 DP |
| 区间合并、最后断点/最后操作 | 区间 DP |
| 固定维状态重复 `1e18` 步 | 转移矩阵快速幂 |
| mask 需要统计所有子集/超集 | SOS DP |
| 数字范围巨大，条件只看数位历史 | 数位 DP |

“矩阵快速幂题”的难点通常不是矩阵乘法，而是先找到固定维状态。如果状态维数随 `n` 增长，矩阵幂大概率不是正确方向。

## 七、字符串结构怎样分工

| 需求 | 首选 |
|---|---|
| 一个模式串在文本中出现位置 | KMP |
| 每个后缀与整串前缀的 LCP | Z 函数 |
| 大量子串相等、路径字符串比较 | 双模滚动哈希 |
| 前缀查询、字典 | Trie |
| 多模式匹配 | AC 自动机 |
| 回文半径、最长回文 | Manacher |
| 全部后缀排序、相邻后缀 LCP | 后缀数组 |

哈希不是绝对正确结构。普通题可用双模降低风险；若题目允许卡哈希，或答案必须确定，改用后缀数组、KMP/Z、Trie 等无碰撞方法。

KMP 的 `failure` 不只用于匹配。把 border 看成一棵树后，它还可以做前后缀计数、祖先跳转和等价关系合并，这正是区域赛银题常见升级方式。

## 八、数学和位运算先检查前提

- 费马逆元要求模数为质数且底数与模数互质；一般模数用 exgcd。
- 组合数阶乘板通常要求预处理范围小于质数模；否则考虑 Lucas 或别的方法。
- 两个模数不互质时不能直接套普通 CRT；使用 [广义 CRT](../03-silver/chinese_remainder.cpp)。
- `long long` 乘法可能在取模前溢出，使用 `__int128`。
- SOS DP 要明确求子集和还是超集和；循环位必须放在外层。
- 线性基解决的是 xor 线性空间，不是一般的“位运算题”。

## 九、几何模板先统一语义

几何 WA 很多不是公式错，而是边界定义不统一：

- 线段是闭区间还是开区间？端点接触算相交吗？
- 凸包是否保留共线边界点？
- 坐标是整数还是浮点？整数叉积会不会溢出？
- 浮点比较使用什么 `EPS`？输出误差要求是什么？

[二维整数几何](../03-silver/geometry_base.cpp) 默认闭线段、端点接触算相交、叉积用 `__int128`；[Andrew 凸包](../03-silver/convex_hull.cpp) 是否保留共线点要按题意改弹栈条件。

## 十、模拟、观察、构造为什么也要“模板化”

这三类题通常没有一段万能代码，但有固定工作流：

### 模拟

写状态表：每个字段由哪一种事件修改、同一时刻的更新顺序、是否允许重复事件。一个输入事件尽量只在一处修改状态。

### 观察题

用 `n <= 8` 暴力生成答案，按奇偶、差分、gcd、极值和相邻关系分类；提出结论后补“必要性 + 充分性”。

### 构造题

先列不可行情形，再写构造；最后像 checker 一样逐条验证长度、范围、唯一性、目标性质和操作次数。

2024–2025 报告显示，这套流程对铜牌低罚时的价值不亚于再多背一个高级数据结构。

## 十一、把模板改进题目时的固定流程

1. 复制后先改 `MAXN`、类型、下标和输入语义。
2. 在纸上写出模板原本维护的信息，以及题目新增的信息。
3. 只改 `Node/状态 → merge/转移 → apply/down` 三层，不同时重构 I/O 和结构。
4. 手造最小规模、全相同、全不同、无解、重复、极值和断图。
5. 若是贪心、构造、复杂数据结构，写小暴力随机对拍。
6. 对拍失败先保存输入，再缩小反例；不要靠继续随机碰运气。
