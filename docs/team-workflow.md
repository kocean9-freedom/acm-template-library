# 三人队五小时流程与模板维护

算法水平相近的队伍，差距往往来自题目分配、开题止损、上机冲突和罚时。模板库只有嵌入协作流程才有价值。

## 开场 20 分钟

三人各看不同题，每题只做初筛，不急着写完整解法。记录四项：

```text
预计难度：签到 / 稳定题 / 突破候选 / 暂放
核心转化：一句话
预计代码量：短 / 中 / 长
风险：证明、边界、实现、交互、精度
```

第 10 分钟交换题面，第 20 分钟确定：第一台机的签到题、第二位纸上推稳定题、第三位继续筛银牌候选。

## 20–90 分钟：封稳定题包

- 最短、最确定的题先上机，不按题号顺序。
- 实现者编码时，另一人必须同步手造边界，不围观屏幕。
- 一道签到题出现两次非语法罚时，立即换人复核题意和状态更新顺序。
- 稳定题算法超过 80 行时，先确认是否把简单模型写重了。

目标是低罚时拿下 2–4 题，而不是所有人同时研究最有趣的题。

## 90–240 分钟：选择第 k+1 题

每条银牌候选使用同一止损线：

- 15 分钟：应出现可验证的压缩对象，例如状态、mask、failure 链、势能、子树贡献或直线。
- 25 分钟：应能写出复杂度和至少一个正确性抓手。
- 35 分钟：若仍只有局部观察，没有闭合转移/证明，切换到第二候选。

若推导已闭合但代码长，由模板最熟的人实现；另一人写暴力或 checker；第三人继续维护未过题和候选表。

## 240–300 分钟：收口

- 不再同时开两道长题。
- 对接近完成的题做输入规模、类型、空集、重复、下标和输出格式检查。
- 有可运行正解和暴力时优先对拍；没有暴力时至少跑极小、全同、链、星、断图等结构。
- 最后 15 分钟谨慎大改核心结构，除非已有明确反例定位。

## 三个角色不是固定的人

| 角色 | 当前职责 |
|---|---|
| 主推导 | 给出状态、转移、复杂度和关键证明，不边写边猜 |
| 实现者 | 把已闭合推导翻成代码，控制接口和下标 |
| 反例手 | 造边界、写暴力、检查题意和输出限制 |

每道题可以换角色。队内最危险的状态是三个人都在当“半个推导者”，但没人对代码负责。

## 模板的赛前维护

### 每周

- 从 A 级模板随机抽两个，不看代码重写。
- 从 B 级模板抽一个做模板题和一次随机对拍。
- 记录本周真实用到、误用和差点忘记的模板。

### 每月

- 删除从未使用且没人能解释的重复实现。
- 把连续出现三次的能力从 C 升到 B。
- 对所有 B 级模板重新跑编译与测试。
- 选一场旧区域赛做五小时模拟。

### 大赛前

1. 固定编译器、C++ 标准、索引风格和常用宏。
2. 运行 `CXX=g++-15 bash scripts/check.sh`。
3. 只打印团队真正会改的内容；完整仓库用于赛前学习和赛后复盘。
4. 三个人各自找一次常用模板，确认目录和关键词能在 30 秒内定位。

## 复盘格式

每道未通过或高罚时题只记录四项：

1. 识别核心转化用了多久。
2. 证明或状态在哪里卡住。
3. 第一版代码属于读错、边界、溢出、状态、实现还是调试问题。
4. 下次真正可复用的 10–30 行是什么。

不要只写“这题是 DP/图论”或“手速慢”。这种标签不会改变下一场的行为。
